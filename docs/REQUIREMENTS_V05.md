# 0.5 需求确认与验收口径

依据：北京时间 2026-10-18 本轮反馈及后续补充。新要求覆盖旧文档中冲突的描述；版本为 `0.5.0-phase1`。实际完成证据集中在 [acceptance.json](acceptance.json)，本页记录产品约定。

## 本轮决定

| 项目 | 确定行为 | 验收方法 |
| --- | --- | --- |
| 评审与实际服务 | 同一 Sites 链接继续评审前端；真人多人服务部署到用户自有主机，由用户本地 Codex 执行 | Sites 明示“界面评审”及当前浏览器记录范围；自有服务用独立会话实际进入同一房间 |
| 昵称入场 | 首次填昵称，无密码、验证码、邀请码或审批；受邀链接无需账号，填昵称后继续进入该房 | 新浏览器走邀请链接，填昵称后进入正确房间；刷新沿用当前身份 |
| 昵称与权限 | 昵称用于显示，不是账号凭证；可以重名，不能靠填写同名取得他人角色、房主权限或历史私密记录 | 同名的两个独立会话仍是两个成员；非房主操作返回服务端拒绝 |
| 旁观 | 房间默认允许旁观，受容量和本房移出限制；“关闭补位”只关闭新演员选角，不关闭旁观 | 旁观者看到舞台历史，不能发送舞台消息或读取后台；开放时可选择空角色 |
| 移出成员 | 未结束房间的房主可移出其他成员，包含演员和旁观者；不能移出自己 | 确认后目标连接关闭、角色释放，当前会话不能重入该房；已有消息保留 |
| 入退场记录 | 入房、选角、主动退出、被房主移出产生舞台系统消息，并存入历史 | 另一独立会话实时看到；刷新、分页和重连后仍在且不重复 |
| 网络暂离 | 关闭页面、断网或重连不会自动释放角色，也不反复生成入退场消息 | 断线期间仍占角，重连补齐；重复 join/claim/leave 不刷系统消息 |
| 已结束记录 | 结束后回看不继续追加访客足迹；原演出记录保持只读 | 新读者进入和原成员回看不增加演出消息 |
| 人物素材 | 两团十人使用可核对的原始人物素材；头像与详情对应同一角色、同一套形象 | 核对来源、姓名、服装、原图尺寸及小头像与详情的对应，不以 AI 重绘替代原图 |
| 贴纸文字 | 正常显示的已发送贴纸下方不出现“害羞”等文件名或标签 | 舞台、后台已发送贴纸只有图像及正常消息作者／时间；搜索、无障碍文本与缺图回退仍可辨认 |
| 贴纸白边 | 去掉页面额外消息框，保留原图；不把 162×162 原图强行放大或自动抹去人物附近白色 | 核对浅深主题下原图轮廓；原图自带描边与页面边框分开判断 |

## 系统消息规则

系统消息属于舞台聊天时间线，使用数据库保存的消息序号参与同步与分页。文案在事件发生时保存，之后改昵称不改写旧消息。

示例：

- `小八 以观众身份进入了房间。`
- `小八 作为 长崎素世 入场。`
- `小八（长崎素世）离开了房间。`
- `小八（长崎素世）已被房主移出房间。`

最终标点与措辞以实现为准。普通客户端不能自行提交 `kind=system`，也不能指定其他人的作者身份。重新打开仍持有成员资格的房间属于恢复连接，不是又一次入房；主动离场后正式重入才追加新的入房记录。不会为升级前的历史补造入退场记录。

## 当前能力边界

本轮没有增加账号注册、密码管理、跨设备找回、按昵称认领旧会话、禁止旁观的私密房、全站账号封禁或房主转让。房间移出针对当前匿名会话，不能保证用户换浏览器后仍被识别为同一人。后续要做持久账号与更强治理时单独设计，不把“随便输入一个名字”当作身份认证。

Sites 不提供切换虚构其他用户来演示多人，也不模拟他人的回复。旁观、踢出和群聊通知的真实验收使用完整 FastAPI 服务的两个或三个独立会话。三个普通标签页共享 Cookie，不能代表三个人。

## 接续入口

交给本地 Codex 的完整任务见 [CODEX_HANDOFF.md](CODEX_HANDOFF.md)。本地 Codex 接手服务运行、浏览器与手机验收、目标机检查和部署；不再以当前 ChatGPT 获得设备控制权作为前置条件。日常视觉反馈仍可在既有 Sites 上更新，部署与评审共同维护一份源码。
